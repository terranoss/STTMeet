# Extract the transcription pipeline behind a headless-callable seam

The chunk loop, resume-from-checkpoint, tail-context carry and transcript assembly lived only as methods on `STTMeetApp`, a `CustomTkinter` subclass. That made ~577 lines of orchestration reachable only by constructing a window, left the whole loop untested, and forced the worker thread to read Tk variables from off-thread — which the code's own snapshot mechanism existed to prevent. We extracted the orchestration into `src/pipeline.py` as `run_pipeline(settings, observer, cancel_event)`, a plain function taking a `PipelineSettings` dataclass and reporting through a `PipelineObserver`. Two adapters sit on the seam from the start: the desktop app, and a `--headless` flag on `main.py`. Taking settings as a dataclass rather than reading them from widgets closes the thread-safety leak structurally — there is no widget left to read. The observer receives i18n keys and kwargs rather than translated strings, so the pipeline carries no locale and the headless adapter needs no translation table to run. Session saving stays with the callers: the pipeline knows how to write a **checkpoint**, but what constitutes a saved session is the desktop app's concern. A function was chosen over a class because a run's state is passed in and reported out, never mutated across calls, so a class would add interface surface without adding capability.

Consequence worth knowing: the pipeline module cannot import anything from `src/ui/`. If a future change needs the **chunk monitor** or the main transcript view, the answer is to report an event and let the adapter render it, not to reach back into the GUI.
